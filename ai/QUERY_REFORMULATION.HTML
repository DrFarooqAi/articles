What is Query Reformulation?

Query Reformulation is the process of modifying, expanding, or restructuring a user's original question before it's sent to the retrieval system. The goal is to bridge the gap between how humans naturally ask questions and how retrieval systems best understand them.

🌍 The Translation Analogy

Imagine you're in a foreign country and you ask a local for directions using broken phrases. They might understand your intent, but they could also misinterpret you. Now imagine you have a translator who converts your broken phrases into clear, grammatically correct sentences in the local language. Suddenly, you get much better directions.

Query reformulation is that translator. It takes the user's raw input and transforms it into a form that the retrieval system can work with more effectively.

Key Insight: Query reformulation doesn't change what the user wants — it changes how the system understands what they want.
2

Why Query Reformulation Matters in RAG

Traditional RAG systems assume users will ask clear, well-structured questions. In reality, user queries are often messy, ambiguous, or incomplete.

🌫️

Vague or Ambiguous

"Tell me about that thing"

🎯

Too Specific or Narrow

"What is the exact molecular weight of compound X-47B in the 2019 study?"

🔗

Multi-part or Complex

"How does climate change affect agriculture, and what are the economic implications?"

Different Terminology

"How do I fix a broken screen?" vs. "Display replacement procedure"

❓

Missing Context

"What did he say?" (Who is "he"? What conversation? When?)

Without query reformulation, these messy queries lead to poor retrieval, which leads to poor answers. Query reformulation is the critical preprocessing step that ensures your retrieval system gets the best possible input.

The 6 Core Techniques

Let's explore the major techniques, from simplest to most advanced.

1

Query Rewriting / Paraphrasing

Low Complexity • Low Cost

What it is: Transforming the original query into a clearer, more precise version while maintaining the same intent. An LLM rewrites the query using better phrasing, clearer terminology, or more explicit language.

Original Query

"How do I fix it when my phone won't charge?"

Rewritten Query

"What are the troubleshooting steps for a smartphone that is not charging properly, including checking the charging cable, cleaning the charging port, and testing with different power sources?"

def rewrite_query(original_query: str, llm) -> str:
    prompt = f"""
    Rewrite the following user query to be more clear, specific,
    and suitable for document retrieval.
    Maintain the original intent but use precise language.
    
    Original query: {original_query}
    
    Rewritten query:
    """
    return llm.generate(prompt)

Best for: Vague, poorly phrased, or informal queries where a single clear rewrite improves retrieval.

2

Multi-Query Approach

Medium Complexity • Medium Cost

What it is: Generating multiple variations of the original query to cast a wider retrieval net. Instead of asking one question, the system generates 3-5 different ways to ask the same question, retrieves documents for each, then deduplicates and ranks the results.

Example: "What are the benefits of meditation?"

1️⃣ "What are the health benefits of regular meditation practice?"

2️⃣ "How does meditation improve mental and physical well-being?"

3️⃣ "What scientific evidence supports the positive effects of meditation?"

4️⃣ "What are the psychological and physiological advantages of meditation?"

def multi_query_approach(original_query: str, llm, num_queries=4):
    prompt = f"""
    Generate {num_queries} different versions of the following query.
    Each version should ask the same question but use different
    wording and perspectives.
    
    Original query: {original_query}
    
    Generated queries (one per line):
    """
    queries = llm.generate(prompt).strip().split('\n')
    
    all_results = []
    for query in queries:
        results = vector_search(query)
        all_results.extend(results)
    
    return deduplicate_and_rank(all_results)

️ Trade-off: Higher recall but increased latency and API costs (multiple LLM calls + multiple searches).

3

Query Decomposition

Medium Complexity • Medium Cost

What it is: Breaking down a complex, multi-part question into simpler sub-questions that can be answered independently. The system identifies that a query contains multiple questions or requires multiple pieces of information, then splits it into separate queries.

Original Query

"How does machine learning work, what are its applications in healthcare, and what are the ethical concerns?"

Decomposed Into:

"How does machine learning work? (Explain the basic principles and algorithms)"

🔹 "What are the applications of machine learning in healthcare?"

🔹 "What are the ethical concerns and challenges associated with machine learning?"

def decompose_query(original_query: str, llm):
    prompt = f"""
    Analyze the following query. If it contains multiple questions
    or topics, break it down into separate, simpler sub-questions.
    If it's already a simple question, return it as-is.
    
    Original query: {original_query}
    
    Sub-questions (one per line, numbered):
    """
    sub_queries = llm.generate(prompt).strip().split('\n')
    return [q.split('. ', 1)[1] if '. ' in q else q for q in sub_queries]

Step-Back Prompting

Medium Complexity • Medium Cost

What it is: Asking the LLM to first identify the underlying principles or concepts behind a specific question, then using that broader context to guide retrieval. Instead of directly answering the specific question, the system asks "What general principle or concept does this question relate to?"

Example

Original: "Why did the 2008 financial crisis happen?"

Step-Back: "What are the fundamental causes of financial crises in general?"

Result: Documents about financial crisis theory, economic bubbles, regulatory failures, and systemic risk — combined with 2008-specific context.

def step_back_prompting(original_query: str, llm):
    # Step 1: Generate step-back question
    step_back_prompt = f"""
    What general principle, concept, or broader topic does the
    following question relate to? Formulate a more general
    question that captures the underlying concept.
    
    Original question: {original_query}
    """
    step_back_query = llm.generate(step_back_prompt)
    
    # Step 2: Retrieve using both queries
    specific_docs = retrieve_documents(original_query)
    general_docs = retrieve_documents(step_back_query)
    
    # Step 3: Combine and generate answer
    combined_docs = merge_and_deduplicate(specific_docs, general_docs)
    return generate_answer(original_query, combined_docs)

HyDE (Hypothetical Document Embeddings)

Medium Complexity • Medium Cost

What it is: Generating a hypothetical answer to the query, then using that hypothetical answer as the search query instead of the original question. The LLM writes what a relevant document would look like if it contained the answer.

Example

Original: "What is the capital of France?"

Hypothetical Doc: "Paris is the capital and largest city of France. Located in the north-central part of the country, Paris has been a major European center for art, fashion, gastronomy, and culture for centuries."

def hyde_retrieval(original_query: str, llm, vector_db):
    # Step 1: Generate hypothetical document
    hyde_prompt = f"""
    Write a detailed paragraph that would answer the following
    question. Focus on being comprehensive and using the same
    terminology that would appear in relevant documents.
    
    Question: {original_query}
    """
    hypothetical_doc = llm.generate(hyde_prompt)
    
    # Step 2: Embed and retrieve
    query_embedding = embed(hypothetical_doc)
    return vector_db.search(query_embedding, top_k=10)
6

Multi-Hop Reasoning with Dependency Resolution

High Complexity • High Cost

What it is: An advanced form of query decomposition where sub-queries may depend on answers to previous sub-queries, creating a chain of reasoning. The system breaks down a complex question into a sequence where later questions reference answers to earlier ones.

Example

Original: "Who is the CEO of the company that acquired GitHub?"

Sub-Query 1: "Which company acquired GitHub?" → Microsoft

Sub-Query 2: "Who is the CEO of Microsoft?" → Satya Nadella

Final Answer: "Satya Nadella is the CEO of Microsoft, the company that acquired GitHub."

def multi_hop_query(original_query: str, llm, max_hops=3):
    current_query = original_query
    context = ""
    
    for hop in range(max_hops):
        sub_query_prompt = f"""
        Given the original question and any information gathered
        so far, what is the next specific question we need to
        answer? If we have enough information, return "DONE".
        
        Original question: {original_query}
        Context so far: {context}
        """
        sub_query = llm.generate(sub_query_prompt)
        
        if sub_query.strip().upper() == "DONE":
            break
        
        docs = retrieve_documents(sub_query)
        answer = generate_answer(sub_query, docs)
        context += f"\n{sub_query}: {answer}"
    
    return llm.generate(f"Original: {original_query}\nContext: {context}")

Decision Framework: When to Use What

🎯 Use Query Rewriting when:

  • • Users ask vague or poorly-structured questions
  • • You need a simple, low-cost improvement
  • • Latency is critical (real-time applications)

🌐 Use Multi-Query when:

  • • You want to maximize recall
  • • The query could be interpreted multiple ways
  • • You have budget for additional API calls

Use Query Decomposition when:

  • • Questions contain multiple distinct topics
  • • Users ask compound questions ("and", "or", "also")
  • • Different parts require different document types

🔭 Use Step-Back Prompting when:

  • • Questions are highly specific but require general context
  • • You need to ensure foundational knowledge is included
  • • The domain requires understanding of underlying principles

📝 Use HyDE when:

  • • There's a mismatch between question phrasing and document language
  • • You're working with technical or domain-specific content
  • • Standard semantic search isn't finding relevant documents

🧠 Use Multi-Hop when:

  • • Questions require chaining multiple pieces of information
  • • Users ask "Who/What/Where" questions about entities mentioned in other contexts
  • • You need complex reasoning over multiple documents

Combining Techniques for Maximum Effect

The most powerful RAG systems don't rely on a single technique — they combine multiple approaches strategically based on query complexity. 

def advanced_query_reformulation(original_query, llm, vector_db):
    # Step 1: Classify query complexity
    complexity = classify_query_complexity(original_query, llm)
    
    if complexity == "simple":
        # Simple query: just rewrite for clarity
        rewritten = rewrite_query(original_query, llm)
        return retrieve_documents(rewritten, vector_db)
    
    elif complexity == "compound":
        # Compound query: decompose and handle each part
        sub_queries = decompose_query(original_query, llm)
        all_docs = []
        for sub_query in sub_queries:
            # Use multi-query for each sub-query
            variants = generate_variants(sub_query, llm, num=3)
            for variant in variants:
                docs = retrieve_documents(variant, vector_db)
                all_docs.extend(docs)
        return deduplicate_and_rank(all_docs)
    
    elif complexity == "multi-hop":
        # Multi-hop: use step-by-step reasoning
        return multi_hop_query(original_query, llm)
    
    else:
        # Complex/ambiguous: use HyDE + multi-query
        hypothetical = generate_hypothetical_doc(original_query, llm)
        variants = generate_variants(hypothetical, llm, num=3)
        all_docs = []
        for variant in variants:
            docs = retrieve_documents(variant, vector_db)
            all_docs.extend(docs)
        return deduplicate_and_rank(all_docs)

Implementation Considerations

⏱️ Latency Management

Query reformulation adds latency. Here are three strategies to manage it:

Strategy 1: Asynchronous Processing

Start reformulation while showing loading UI. Users perceive faster response times when they see progress.

Strategy 2: Caching Reformulated Queries

Cache common query patterns. If "how to fix phone" has been reformulated before, reuse the result.

Strategy 3: Tiered Approach

Try simple retrieval first. If confidence is low, apply reformulation. Only use complex techniques when necessary.

💰 Cost Optimization 

def cost_aware_reformulation(query, budget_remaining):
    if budget_remaining < 0.01:  # Less than 1 cent
        return query  # Skip reformulation
    
    if budget_remaining < 0.05:
        return rewrite_query(query)  # Cheap option
    
    if budget_remaining < 0.20:
        return multi_query_approach(query, num_queries=3)
    
    return advanced_reformulation(query)  # Full pipeline

def domain_aware_reformulation(query, domain):
    if domain == "legal":
        prompt = """
        Rewrite this legal query using precise legal terminology.
        Include relevant legal concepts and citations format.
        Query: {query}
        """
    elif domain == "medical":
        prompt = """
        Rewrite this medical query using standard medical terminology.
        Include relevant medical codes (ICD-10, CPT) where applicable.
        Query: {query}
        """
    return llm.generate(prompt.format(query=query))

Common Pitfalls & How to Avoid Them

⚠️ Pitfall 1: Over-Reformulation

Problem: Changing the query so much that it loses the user's original intent.

def validate_reformulation(original, reformulated, min_similarity=0.7):
    similarity = cosine_similarity(embed(original), embed(reformulated))
    if similarity < min_similarity:
        return original  # Fall back to original
    return reformulated

⚠️ Pitfall 2: Infinite Loops in Multi-Hop

Problem: Multi-hop queries that never reach "DONE" and keep generating sub-questions.

Problem: Generating too many sub-queries or too much context, exceeding the LLM's context window.

def safe_context_management(context, max_tokens=3000):
    current_tokens = count_tokens(context)

Conclusion

Query reformulation is not just a nice-to-have feature — it's a critical component of any production-grade RAG system. By transforming raw user queries into optimized search requests, you can dramatically improve retrieval accuracy and, ultimately, the quality of your AI's responses.

Key Takeaways

1

Start Simple: Begin with query rewriting and measure the impact before adding complexity.

2

Match Technique to Problem: Use multi-query for recall, decomposition for complex questions, HyDE for semantic gaps, and multi-hop for reasoning chains.

3

Balance Trade-offs: Every technique adds latency and cost. Choose based on your specific requirements and constraints.

4

Combine Strategically: The most powerful systems use multiple techniques in a tiered, adaptive approach.

5

Measure Everything: Track precision, recall, latency, cost, and user satisfaction to continuously improve.

6

Learn from Feedback: Use user interactions to refine your reformulation strategies over time.

Final Thought: Query reformulation is the bridge between human intent and machine understanding. Master it, and you master the foundation of effective RAG systems.
